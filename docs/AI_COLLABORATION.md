# AI collaboration and verification

**Disclosure:** Identity is a human-directed software project developed with assistance from AI systems. AI has contributed to discussing its purpose, evaluating architecture choices, writing documentation and preparing experimental software changes. The exact scope of individual contributions should be recorded where known.

## Roles

- **Human owner:** Establishes priorities, requirements, constraints, test expectations, and whether experiments become Alpha, Stable or Main.
- **AI assistants:** Can research, propose alternatives, draft documentation, implement experimental code, write tests and review results. Their statements are not independent evidence of correct operation.
- **Contributors:** Should acknowledge material AI assistance in commits, pull requests or experiment notes where practical, without claiming every line was generated by AI when that is not known.

## Verification rules

1. Clearly identify design proposals, source-code implementations, automated tests and real observed runtime behavior.
2. Include actual branch and full commit SHA, environment, test commands, limitations and side effects in experimental reports.
3. Do not claim a feature works merely because an AI produced code, a unit test passed, a UI returned HTTP 200 or a model declared success.
4. Verify external GitHub operations, security enforcement and service-to-service behavior against real authorized services before owner acceptance.
5. Keep human approval authoritative for branch promotion, account permissions and impactful changes.
